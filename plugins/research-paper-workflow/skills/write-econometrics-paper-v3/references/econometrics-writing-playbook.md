## 结果卡与段落合同

为每项核心结果先写结果卡：

1. 对象和条件；
2. 最窄可辩护结论；
3. 直觉或失败机制；
4. 对估计、检验、模拟、计算或应用的含义；
5. 正式落点和状态 ID。

用 `function`、`claim`、`evidence`、`inference limit`、`bridge` 检查段落；仅为新主张、高影响修改或实际交接保存合同。合同不成立时，先移动、拆分或删除段落，不把结构问题润色成流畅文字。

## 标题与摘要

标题优先表达问题、对象或关键结果；只有方法本身是贡献时才把方法放在标题中心。不要用固定字数或标题公式替代目标期刊和论文类型判断。

摘要按以下功能组织，而不强制固定句数：

- 问题与环境；
- 精确摩擦；
- 核心动作；
- 主要保证或结果；
- 有限样本/应用证据与用途；
- 必要边界。

摘要只写正文已兑现内容。不得把 pointwise 结果写成 uniform，把 size control 写成 power dominance，把某组 DGP 下的表现写成一般优越性，或把相关性应用写成因果结论。

让读者第一次读就能识别研究问题、方法动作与主要结果。把过密的技术限定移到它们真正需要的位置，保留会改变读者理解的边界；不要让实现细节遮住研究问题。一般方法已包含多个主要目标、估计器类别或检验情形时，摘要应准确概括这些已完成内容，不能仍只写旧版的一个特例，也不能列入尚未验证的扩展。

## 引言与文献定位

按读者功能组织引言：

1. 说明重要问题和具体统计/经济决策场景。
2. 给出最近邻方法或解释，揭示可定位摩擦。
3. 用最小例子、公式、反例或失效机制让摩擦可见。
4. 交代核心动作及其为何作用于该摩擦。
5. 按结果而非按章节陈述贡献。
6. 把每项贡献绑定到定理、Monte Carlo、计算或应用证据。
7. 公平说明最近邻差异、适用边界和论文路线。

文献综述不是作者—年份列表。按问题、对象、假设、方法或推断差异分组；比较相同 estimand、null、信息集和数据环境。最近邻文献必须核对版本，不能仅凭标题或摘要声称“首次”。

问题/insight/背景及最近邻统计量归约的具体检查见 [reader-facing-writing.md](reader-facing-writing.md)。比较既要检验重复，也要保留有证据的新校准、新证明或范围拓展，不用笼统“已有文献”抹去真实增量。

摘要与引言对贡献范围应一致；更新其中一处时检查另一处及结论，受保护或暂缓修改的部分记录待同步状态。参考文献按其对研究问题的实际作用组织，不为增加数量而堆引；来源核验和引用语法分别检查。

## Setup、识别与方法

按依赖顺序写：

1. 数据结构、观察单位和信息集；
2. 目标对象、null/alternative 或预测目标；
3. 识别条件及其排除的世界；
4. oracle/infeasible 对象；
5. 可行估计量、检验或算法；
6. nuisance、调参、样本拆分和计算步骤；
7. 推断对象和报告方式。

不要把识别假设藏进估计步骤。区分“对象存在”“对象被识别”“估计量一致”“统计量有极限分布”“bootstrap 有效”“算法可实际运行”。

通用目标、具体例子与方法构造的衔接，以及直接可读的假设表达，见 [reader-facing-writing.md](reader-facing-writing.md) 的“从研究问题自然引出理论”。按科学依赖调整以上顺序，不强制为每个环节建立独立小节。

## 理论结果

在相关问题和定义已交代后，先给读者要记住的结论，再给条件、正式陈述及必要解释。对影响读者判断的强假设，在合适位置简要说明：

- 数学作用；
- 排除的经济/统计情形；
- essential、sufficient 还是 convenience；
- 放松后哪个结论失效。

定理、引理和推论之间建立依赖图。按用户用途选择直觉解释、proof sketch 或完整证明，并标清层级；完整证明放在最能维持主线的位置，而不是机械地全部移入附录。论文证明的具体推理完整性遵循理论技能，不因切换成简报就声称新增了证明。

依赖图用于组织与核查，不默认作为稿件中的路线图或清单。陈述精简、整段证明、技术步骤是否单列，以及仅替换 proof 环境的边界，见 [reader-facing-writing.md](reader-facing-writing.md) 的“紧凑的陈述与完整的证明”。

对局部备择、弱识别、非正则、方向可微、uniformity、dependence 或 bootstrap 结果，明确概率空间、收敛方式、索引集合和条件是否一致。

## Monte Carlo

每个设计必须回答“它审计哪项理论或实现风险”。至少记录：

- DGP 公式、参数、样本量和误差/依赖结构；
- null、fixed/local alternative 或边界情形；
- 比较方法和公平调参规则；
- 重复次数、seed 生成策略和并行不变性；
- 估计偏差、RMSE、size、power、coverage、interval length 等指标定义；
- Monte Carlo standard error 或足以判断模拟噪声的精度信息；
- 失败、警告、非收敛和缺失结果处理。

主表应区分设计因素与方法因素；图表标题和注释应自包含。不要只展示新方法占优的 DGP，不要在看完结果后静默更换基准、带宽、bootstrap 或重复次数。

正式稿不能只呈现运行代码中的 DGP ID 和方法缩写。首次给出方法全名、必要的 DGP 公式或解释，以及读者能查到的对应；设计较多时可用简短设计表/方法表或表内分组，不机械固定表数。根据比较问题安排 size、power、不同检验与场景，避免将缺失的结果、另一检验的 size 或不匹配的 null 基准混为一组证据。正文突出主要发现与判断依据，完整补充结果按用途放入附录或结果文件，保留用户指定的展示范围和已有可复用结果。

比较方法注明原始论文，核对显示名称、缩写与实际实现的统计量一致；不能仅凭代码标签认定方法身份。先确认 DGP 是否满足该方法的原假设，再把拒绝率称为 size 或 power。表格按实际完成的重复次数和结果来源生成，不把计划次数当实际次数；不适用、未运行和运行失败在表注中区分。精度信息可按用途放在表注、附录或复现记录，不因正文简洁而抹去。

表格更新后同步核对正文分析、表注、方法/DGP 说明及对应附录，不能新表配旧分析。布局以清楚比较和有效使用版面为准：适当合并重复标签、居中并利用版心宽度，长表重复续页表头、表注与表格同宽，检查编号和空白；不靠极小字号或压扁比例换取紧凑，不固定列数、表数或附录字母。

Monte Carlo 的正文分析先确定设计目的、主要规律、少量代表数字及影响判断的
实质代价，再连成简短叙述；不逐格复述，也不用“总体表现良好”替代结果。
校准失败、比较反转或明显不占优不能因压缩消失。较高的 raw rejection 只有在
对应 null 和 same-size 比较资格成立时才支持功效优势；校准组件的消融与外部方法
比较分别说明，不能把两种变化混作一个效果。

弱/中信号设计若用于避免拒绝率饱和、辨别方法差异，在设计首次出现处简述目的；
沿用实际设定和选择时间，不把结果出来后调整的信号说成事前冻结。详细设定、
MCSE 与失败记录可放合适附录/表注，不规定通用段数、信号数或单元数。

## 实证应用

应用必须说明：

- 数据、样本、变量和版本；
- 对象、识别或解释边界；
- 方法相对现有做法改变了哪个判断；
- 不确定性、调参和诊断；
- 哪些结论只是 illustration，哪些可以作实质解释。

真实数据上的可运行性不是有效性的证明。若应用不承担验证功能，明确写成 illustration 或 use case。

## 经济量级、零结果与边界

统计显著性与经济/实质量级分开报告。把系数转换为有意义单位，说明分母、基准、总体和变化尺度；比较必须选择可解释基准，而不是任意放大效果。

对零结果区分：

- 区间足够窄，可排除预先界定的实质效应；
- 区间很宽，只能说明证据不足；
- 研究设计或检验对相关备择功效不足；
- 多重检验或选择后推断改变解释。

不要把 fail to reject 写成证明零效应。对机制只在设计能识别机制时使用确定措辞，否则写为一致性证据、排除性证据或一种解释。

对影响读者判断的异常，在对应结果首次出现的段落或表注中交代，不把说明只藏在末尾局限性：

- 先核查数值、指标定义、比较口径和可用诊断；把统计现象、识别/信息限制与求解失败分开。
- 明确哪些原因已有推导、反例、消融或复算支持；其他原因写为可能解释，并说明尚缺哪个能区分它们的检查。未运行的诊断不能写成已排除某原因。
- 没有查明原因时说明结果与解释边界，继续可完成的分析；不能用一个顺耳机制代替证据，也不为每个无关小波动扩成研究任务。
- 单独改变误差分布、依赖结构或调参后分别表现稳定，只支持各已测情景；没有联合设计或相应理论，不写成同时存在这些因素时仍然稳健。表图与文字保留实际组合和覆盖范围。

## 结论、附录和复现

结论重建“学到了什么、在何种条件下成立、仍不能回答什么”，不复制摘要，不写无证据政策外推。

附录按正文依赖组织：定义和辅助结果、证明、额外模拟、实现细节、稳健性、数据与复现。正文中引用每个保留的附录产物；未被任何主张使用的产物应删除、降级为记录或解释保留理由。

将表图映射到生成程序、输入、样本/DGP 和支持主张。说明软件版本、随机性、运行顺序、失败处理和受限数据访问边界。

## Reverse outline

章节完成后生成：

| 段落 | 功能 | 主题句/主张 | 证据 | 推断边界 | 与下一段关系 |
|---|---|---|---|---|---|

检查：

- 每段是否只承担一个主要功能；
- 主题句是否服务章节目标；
- 证据是否真正支持主题句；
- 段落顺序是否遵循读者依赖，而非研究过程时间线；
- 删除该段是否暴露缺失依赖，还是反而让主线更清楚。

## 科学图形与图注解释

作图前确定每张图承担的任务：检验决策、过程形状、相对构成或方法比较；并绑定
真实结果文件、生成代码及当前版本。沿用项目环境或作者选定绘图工具，不能用
图像生成模型代替科学绘图或修造实验结果。只改视觉样式时保留原始数据与统计对象。

根据实际转换核对图注和正文的允许解释：

| 图形操作或对象 | 图注必须说明及不可推出的结论 |
|---|---|
| 每幅单独归一化的热图 | 归一化分母/范围；可示图内相对形状，不能凭亮度比较不同图的总强度 |
| 过程平方、绝对值或其他去符号变换 | 变换及单位；不能恢复正负方向，也不能把亮区自动叫作局部显著性 |
| 统计量的积分/加权组成 | 权重、积分域和是否精确对应程序；示意或近似面积不能冒称精确统计量分解 |
| 拒绝频率及其方法差 | null/alternative、显著性水平和比较资格；null 点的差不是 power gain |
| 阴影或阈值标记 | 它是置信带、拒绝域、正值部分还是装饰；不能用阴影外观代替不确定性或显著性计算 |

没有额外校准时使用实际对象名称，如 rejection-frequency difference；已核验的
power 比较仍可称 power，不一律禁用。非拒绝仅说明该决策结果，不证明 null 为真。
必要图形信息在图注首次说清，正文解释其研究用途；无需给每幅图添加同一段警告。
