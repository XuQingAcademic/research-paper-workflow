# 有界离线复现审计的条件配方

仅当当前任务明确要求可运行 auditor、audit 报告和归档 replay 工件，并提供对应
manifest / reproduction guide 时使用。文件名、数量和运行次数以实际交付合同为准；
普通结果问答、预算估算或单项代码检查不创建这套工件。不因十分钟等时长自动启用。

在该匹配范围内，可用以下执行顺序：读 request、manifest 和 reproduction guide 后立即建立 deliverables 目录与可运行 auditor；在运行实现测试之前，先让 auditor 能载入配置、归档与焦点 cell 并写出结构有效的结果。supplied implementation tests 只运行一次能够覆盖它们的命令；全量 discovery 已通过后不再重复同一模块的子集。随后按合同完成 replay、逐次统计与实际 manuscript include 追踪，再做定向终检。只有要求字节一致性比较或对应复现风险确实需要时才安排第二次 deterministic replay。使用指定执行主机上满足项目依赖/版本要求的环境，找到适用环境后不继续无目的枚举。优先完成实际要求的工件，不按固定时间比例添加报告或裁剪科学核验。

该流程开始时同时创建 `audit.md` 骨架，先写明身份、公式、待验证项、版本边界和证据上限；不能等所有计算结束后才创建报告。按 reproduction guide 执行适用测试，并在理解接口或诊断失败确有需要时检查测试源码；不能用猜测测试或只迎合断言代替实际不变量核查。一次 replay 的结构与核心统计通过后即可写入已知事实；如果合同要求第二次，明确其比较目的。实际交付与直接检查完成后停止，不为增加日志重复测试或无依据扩大巡检。
