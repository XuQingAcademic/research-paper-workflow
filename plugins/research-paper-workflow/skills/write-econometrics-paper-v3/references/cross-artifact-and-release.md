## 论文依赖图

把论文视为以下依赖链：

```text
Question / estimand
  → assumptions / identification
  → estimator, test, or algorithm
  → theorem and proof
  → Monte Carlo design and metrics
  → empirical design and exhibits
  → abstract / introduction / conclusion
  → supplement / replication / submission material
```

上游变化必须向所有下游产物传播；下游证据变化也必须向上重审主张。不能只更新最先发现问题的段落。

## 一致性检查

### 语义对象

- 摘要、引言、正式定义、定理、模拟和应用是否讨论同一 estimand/null/对象？
- pointwise/uniform、conditional/unconditional、fixed/local alternative 是否一致？
- causal、descriptive、predictive、structural 解释是否越界？

### 数字与设置

- 样本量、时间范围、分位点、显著性水平、带宽、bootstrap 次数和 Monte Carlo 重复数是否一致？
- 表图注释与正文是否使用相同分析样本、标准误和调参？
- 数字差异是否来自合法的样本/规格变化，并明确命名？

在 `paper_state.yaml` 的 `consistency_rules` 中记录关键事实：

```json
{
  "id": "N001",
  "canonical": "5,000 replications",
  "required_in": ["simulation"],
  "forbidden_variants": ["1,000 replications"]
}
```

自动化关键数字一致性只检查声明式字符串。另用 [claim-coverage.md](claim-coverage.md) 对新增/改动正文做有限的反向漏登记提示；未登记数字的含义和实际正确性仍需阅读与程序产物核对。

### 模拟决策的数字与范围

先消费数值模拟的结果交接。已有材料缺少关键计数或条件时，直接核对影响当前主张的原始记录、项目汇总及理论陈述。识别相关方法、事件、比较组与分母。若必须复算，从最小的源数据入口查受影响单元。若只有已舍入比例，按可核实精度写入，保留无法恢复精确分子的状态。

关键误放、错误拒绝或零事件应在稿件读者能找到的位置写成有事件名和观察范围的“次数 / 实际分母”。陈述如果要引用剔除后的比例，一并交代剔除的单位与理由，或指向紧邻的定义。适用范围须明确到改变结论的条件。写清某个压力场景的实际决策后果，以及它是否属于定理约束的集合。已知条件不能从观察数据验证时，写出需要另外支持的假设。有限重复中观察到零次不提供零概率结论。

写完在当前稿件中反查受影响的摘要、正文、表注、结论及实际交付文件。把“任何场景”“均为零”“保证有效”等高风险概括对回它们实际量化的单元和理论前提；一处正确的表述不能消除另一处扩大范围的句子。优先在相关句子或紧邻表注修正，采用项目的计数和表达。可把实际核对证据留在已有结果卡，论文无需添加内部审计格式。

对以放行或认证为研究对象的结果，先在活动结果正文保存这段话。明说哪种决定算误放、工程或模拟观察中有几次、总共评估多少次、哪项前提让定理适用或不适用。在确有全部实验分母和仅获准分母差异时，标清所用口径。待生成的主稿以这段结果为起点，尽快编译并验证正文包含它，确保在润色结论或处理附属文件时已有可用的完整稿件。只有在事实无法核实时，标明事实边界，采用源记录所支持的精度。若适用范围涉及零风险或概率界，保留其实际量词与随机性来源。

来源限定属于结论本身。把来源及计数动作写在数字附近，例如“按图注定义的作者标记，有……条”或“在可读取的图上至少确认……条”。若是已发表设计的独立重跑，正文应能读出是本次复算的观察。给定已核对的来源和整数，可用 [describe_count_evidence.py](../scripts/describe_count_evidence.py) 生成保留限定的两句起草文字。回读最终 PDF 时逐句检查是否将作者标记换成了直接观测、把下界换成精确值、引用本次复算却只留原图定位，或混用了两种分母。编辑可以保留准确且证据充分的有限陈述，只有与当前结果确有依赖的理论条件才随之调整。

### 表图、定理和代码

- 每个核心 claim 是否至少有一个明确 exhibit？
- 每个 exhibit 是否映射到文件、标签、生成程序、输入和状态？
- 正文是否引用所有保留的核心 exhibit？
- 表图中的样本、单位、不确定性和比较规则是否自包含？
- 定理条件是否与摘要/引言措辞匹配？

### LaTeX 与书目

- `\input`、`\include` 和活动主文件是否无缺失、无循环？
- label 是否唯一，ref 是否已定义？
- cite key 是否存在于活动 `.bib`；版本和引用状态是否清楚？
- 附录、补充材料和主文编号是否可定位？

### 修改后的实际成品

按本次约定的活动稿、原稿保护与输出位置检查；用户要求另存新版时保留原稿。跨章节的符号或理论调整核对定义、陈述、证明、算法、表注及解释的必要联动；纯表达修改保留已有数字、结果和受保护内容，不以“全文 polish”自动改变方法或重算实验。

整篇 LaTeX/PDF 交付时完整构建所需主文和补充材料，修复受本次改动影响的未定义引用、重复标签/链接和公式溢出，并查看相关页面；只交局部替换代码时核对对应环境、宏与引用兼容性，不强制制造整篇稿件。用户指定 Overleaf、普通 LaTeX、PDF 或单独中文解释稿时交付对应格式及可用文件链接。核验范围如实报告：符号迁移检查、编译通过与全篇理论重新证明是不同结果。

### 现有终稿的交付顺序

1. 从现有主文件、项目说明或依赖关系确认哪个文件会进入实际终稿。读取足够支撑本次结果的原始输出、可复用汇总和定理条件。证据缺项时，先完成能核实的结果；只有该项数字或适用性取决于缺项时才补查。若能从现有逐次结果确定计数和分母，直接复核相应单元。
2. 把核实的结果写进被主稿实际读入的正文或表注。尽早保存已修改的文件。检查同一主张在摘要、相关段落及结论中的口径。如果保留了不可比的压力场景，写明它的观测结果和适用条件。先完成本轮稿件需要的内容，再做状态记录和可选诊断。
3. 用项目现有的入口构建已编辑版本。检查构建生成的主稿实际包含改动、引用已解析，且保留本次所需的完整章节。发现构建失败时，沿实际错误定位缺失的活动依赖，只处理本次产生或阻断本次交付的问题。审稿包、状态账本、分析历史和其他输出按用户本次的实际交付范围处理。
4. 返回可打开的活动稿源和实际生成的成品，说明核对过的结果。若关键依赖确实缺失，把已写入的稿源、构建错误和受阻产物一并交付。给出真实可用的版本状况。

## 四遍审查

四遍用于整篇论文候选稿，局部修改只执行受影响的检查。已有证据仍绑定同一对象、版本和范围时复用；科学内容变化重新核验相关依赖，格式变化只刷新受影响的渲染。

首次完整初稿交付也按 [初稿交付检查](first-draft-review.md) 完成与当前范围相称的四遍检查。将正式投稿才需要的政策核验、冻结和批准留在后文的发布阶段。

### 第一遍：论证与结构

检查主脊、章节功能、结果顺序、reverse outline、最近邻定位和贡献。不要在这一遍沉迷局部措辞。

### 第二遍：证据与范围

检查假设、识别、理论、代码、Monte Carlo、实证、表图、引用、不确定性和边界。遇到实质变化时返回第一遍。

### 第三遍：学术表达

检查段落功能、术语、符号、主语、动词强度、句间关系、重复、时态和自然学术表达。禁词命中只能作为候选，不作为 AI 身份判断或机械删除理由。

### 第四遍：交付完整性

检查活动文件、引用、编号、附录、元数据、格式渲染、复现说明、动态期刊规则和 release blockers。格式文件需使用对应文档/PDF/电子表格技能做可视化核查。

## 精确候选稿关卡

所有文字修改完成后运行 `freeze_candidate.py`。它：

- 递归解析受管 LaTeX/Markdown 主稿和活动 `.bib`；
- 将相对路径与文件内容生成稳定 SHA-256；
- 记录候选 hash、文件清单、时间和审计摘要；
- 在存在错误级 blocker 时拒绝冻结。

随后以 `--release` 再次运行项目审计。任何受管文件变化都会导致 hash mismatch；重新冻结前不得称候选稿已核验。

候选 hash 只证明“检查的文件集合未变化”，不证明学术正确、引用真实或期刊接受。

## 自动化工具边界

`audit_paper_project.py` 检查结构化、确定性的信号。它不能：

- 验证定理或证明；
- 判断识别是否可信；
- 判断 DGP 是否科学充分；
- 确认外部来源真正支持主张；
- 判断未登记数字是否一致；
- 保证 LaTeX 成功编译或视觉布局正确；
- 代替作者审批、期刊政策核验或复现运行。

为避免越过授权边界，审计器拒绝读取解析到项目根目录之外的 LaTeX
input、bibliography 或 exhibit 路径。确需共享外部文件时，先将授权副本纳入
受管项目，或由作者明确建立新的项目边界；不要用父目录路径绕过状态包。

报告必须区分 error、warning 和 info。没有自动错误不等于论文可投稿。

## 发布标准

只有同时满足以下条件才称 `submission-ready`：

- 无开放的高严重度研究、证据、引用或跨文件 blocker；
- 主张、exhibit、引用和修订账本处于已核验状态；
- 当前官方期刊 overlay 已填写并人工核对；
- 最终候选 hash 与实际交付物匹配；
- LaTeX/PDF 或其他格式已成功生成并进行视觉检查；
- 必要复现流程已实际运行或明确披露未运行；
- 作者完成内容、作者身份、声明和提交的最终批准；已有适用于该候选稿及操作范围的批准可复用，不要求重复签字。

科学与产物准备已完成、只缺作者提交批准时，交付 `manuscript-ready-for-author-review` 并说明待办；不要因此停止准备或扣留本地成品。其他证据不足时报告 `draft`、`conditionally checked` 或 `not release-ready`，继续处理可完成的修复。`submission-ready` 是提交准备状态，不是所有写作任务的完成标准。
