## 五道关卡

### 1. 发现

用问题、方法、对象、作者、参考文献链和关键词发现候选。搜索结果、聚合页和生成式摘要只能产生候选记录，状态为 `discovered`。

### 2. 元数据核验

至少核对：题名、作者、年份、载体、版本、DOI/稳定 URL。优先使用出版社、Crossref、OpenAlex、正式档案库或作者公开页面。记录使用的权威来源和访问日期。

### 3. 全文主张核验

打开实际引用版本，记录 section/page/theorem/table 等 locator，检查当前句子是否与来源中的对象、条件、方向和范围一致。摘要只能支持摘要明确陈述的内容。

### 4. BibTeX 核验

从 DOI、出版社或可信导出获取条目；不要凭记忆生成。核对 key、entry type、author、title、year、journal/booktitle 和 DOI。工作稿与期刊版不能混为同一条目。

### 5. 正文同步

检查：

- 每个正文 cite key 在活动 `.bib` 中存在；
- 每个重要技术主张在 `citations.yaml` 中有 claim-support 状态；
- 删除句子时评估引用是否仍有用途；
- 更换版本时同步年份、题名、页码和所支持主张；
- 参考文献表中的数据、软件或论文引用符合实际用途和当前期刊规则。

## `citations.yaml` 结构

每个记录建议包含：

```json
{
  "id": "E001",
  "citation_key": "author2025",
  "title": "",
  "authors": [],
  "year": null,
  "venue": "",
  "doi": "",
  "url": "",
  "version": "",
  "metadata_status": "discovered",
  "metadata_source": "",
  "claim_support_status": "unverified",
  "supports_claims": [],
  "locator": "",
  "checked_by": "",
  "checked_at": "",
  "notes": ""
}
```

允许的 `metadata_status`：`discovered`、`verified`、`conflict`、`unavailable`。允许的 `claim_support_status`：`unverified`、`verified`、`partial`、`contradicted`、`not-applicable`。

## 版本与 BibTeX

- 同一研究的工作稿、会议稿和期刊版可能改变定理、结果和题名。
- 优先引用与当前命题对应且读者可定位的版本；正式版并不自动包含工作稿中的所有内容。
- DOI 解析成功只证明标识存在，不证明正文支持当前句子。
- 自动生成的 BibTeX 仍需检查大小写保护、作者顺序、年份和 venue。
- 不任意重命名已有 citation key；若必须改名，执行全项目引用更新和差异检查。
- 作者提供早期稿可能只是解决全文访问问题，不等于授权改用工作论文书目。保留正确的发表版引用，但只能把精确结果归给已核验的对应版本；只在早期稿存在的承重结果必须明确定位该版本，不嫁接到期刊 DOI 下。
- 正文通常按既定模板用作者—年份与必要的结果编号。版本哈希、下载流水和排错过程放内部记录；简化追踪语言不允许混用版本或删除必要科学范围。

## 官方原件与稿用条目

用户要求“官方 BibTeX 完全一致”时，将原样导出与书目事实准确性分别验收，不能
把其中一种冒称另一种。复用现有引用记录及来源目录，不新增强制 schema：

- 保存未经修改的导出 bytes、来源 URL/提供者、取得日期与校验值；出版社导出、
  DOI 注册机构导出、作者提供条目分别标明，不能一概称为出版社原件。
- 活动 `.bib` 是稿用层。若改了 key、LaTeX 保护、作者字段、年份等，逐字段说明
  与哪份原件有何差异以及依据；“字段已核验/规范化”不等于“逐字相同”。
- 若官方自动导出缺作者、拆错姓名或与正式出版页/PDF 冲突，保留原件，不盲目
  覆盖正确条目；依据可核查出版证据准备纠正版本，并报告冲突与差异。不能从
  记忆补字段、伪造导出或为通过字节比较保留已知错误。
- 对明确要求原样交付的任务，交付该原件并说明是否与活动稿逐字一致；有差异时
  如实标为未满足逐字要求，不能自行改口为“事实相同所以完全一致”。无法取得
  指定导出时记录不可取得，继续可完成的事实与主张核验，不制造官方文件。

第一次借用某结果时就区分作品存在、出版字段、所用全文版本/locator、该句话的
支持范围；其中一项通过不替代其余项。背景先例、可迁移工具和本文新增推导的
归因按 [evidence-and-source-discipline.md](evidence-and-source-discipline.md)
执行，排错记录不进入论文的普通叙述。

## 句子级支持

对每个引用句问：

1. 句子包含几个可独立判断的命题？
2. 每个命题由哪个来源、哪个 locator 支持？
3. 来源使用的对象、假设、样本和版本是否相同？
4. 当前动词是否比来源更强？
5. 这是一般背景、精确技术主张、优先权主张还是比较性主张？

“参见”或一串引用不能修复模糊主张。最近邻比较要说明具体差异，不能把未阅读文献写成 strawman。

## 自动检查边界

`check_citations.py` 可以检查：

- cite key 与 `.bib` 双向关系；
- manifest 记录缺失和状态字段；
- DOI/URL 的基本形状；
- 已标记 `verified` 的记录是否有核验者、日期和来源；
- claim-support `verified` 是否有 locator 和支持主张。

脚本不访问网络，也不证明论文存在、BibTeX 正确或来源真正支持句子。人工/代理必须打开来源核对。

## 不可验证时的处理

- 使用明确 placeholder，例如 `[CITATION NEEDED: precise topic]`；不要造一个貌似合理的条目。
- 将状态保持为 `unverified` 或 `unavailable`，并在交付报告列出。
- 若只能核验元数据，避免精确归因结果或定理。
- 若来源与当前句子部分一致，拆句、减弱措辞或增加限定。
- 任何未解决的核心引用在 release 阶段都是 blocker。
